# 仓库与文件治理

## 分支与发布

- `main`：集成分支，通过 PR 进行日常变更。
- `feat/*`、`fix/*`、`docs/*`：短期分支，合并后清理。
- `v0.x.y`：框架版本标签。`0.x` 阶段接口可以调整，但必须在 CHANGELOG 写明。
- 客户产品的收费版本、stable/beta 渠道和构建版本属于配置及发布元数据，不各建一条长期框架分支。

一个产品通常通过私有配置、单独产品仓库和客户端适配器接入本框架。不要把产品私有业务代码塞进公共框架目录，也不要复制框架后长期各自维护无法合并的分支。

## 文件分级

| 文件 | 位置与规则 |
| --- | --- |
| 通用源码、测试、示例、协议与治理文档 | 本公开仓库 |
| 真实产品目录、支付账户、Bot 配置 | 部署方私有配置仓库或配置存储 |
| `.env`、签名私钥、管理密钥 | 密钥存储；禁止进入 Git |
| 账号数据库、硬件摘要、支付流水、审计 | 受控数据库及加密备份 |
| 用户专属产物、发布基线 | 私有对象存储或制品库，按权限交付 |
| `node_modules`、编译目录、测试输出 | 本地/CI 生成，不提交 |

`.gitignore`、源码检查和 CI 是防护层，不能代替提交前审查。公开前运行 `git diff --cached` 和 `pnpm audit:source`。

## PR

贡献者按 CONTRIBUTING 提交并明确接受贡献授权。维护者确认版权来源、协议接受、接口兼容性、测试和安全边界后合并。机器人升级 PR 不自动获得许可审查豁免；依赖保持原许可证。

CI 在 Linux 和 Windows 执行构建、测试、模拟演示、源码检查和运行依赖审计。Actions 使用完整提交 SHA，默认只读权限。PR 不注入生产秘密，不使用 `pull_request_target` 执行外部分支代码。

上游仓库的主分支已配置 Windows/Linux 两项 CI 检查、PR 流程、禁止强制推送与删除、已解决对话要求，并保留管理员旁路处理维护问题。已启用私密漏洞报告。Fork 和通过模板新建的仓库不会自动继承这些设置；请单独配置。贡献授权仍需维护者逐一核对，不由 CI 或分支保护代替。
