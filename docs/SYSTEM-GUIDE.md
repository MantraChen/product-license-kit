# Product License Kit 框架功能与接入手册

更新日期：2026 年 10 月 31 日 CST。适用代码：0.5.0，包含安全恢复、渠道许可证、异常到账和迁移 6。Git 标签固定发布版本，未发布 npm 包。

本手册面向接入产品的开发者与维护者，说明框架负责的业务、外部系统应完成的验证，以及上线前仍需补齐的能力。当前框架已实现账号、永久权益、订单、设备绑定、许可证与分发记录；具体网站、Bot 菜单、工单及真实安装包由产品层实现。

## 1 架构与复用边界

产品网页、社区 Bot 和原生客户端通过产品后端进入框架。框架以 TypeScript 库提供事务化用例，也附带独立 HTTP 参考服务。Node.js 24 与内置 SQLite 是当前运行基础；SQLite 仓储直接参与业务事务，替换 PostgreSQL 需要代码与迁移改造。

| 层次 | 主要职责 | 代码位置 |
| --- | --- | --- |
| 核心策略 | 类型、自然月规则、签名 | src/core |
| 业务服务 | 账号、订单、权益、设备、分发 | src/service.ts |
| 适配器 | SQLite、身份验证、通知 | src/adapters |
| HTTP 边界 | 输入校验、会话、管理认证 | src/http |
| 客户端参考 | 挑战签名与许可证验签 | src/sdk |
| 运维工具 | 初始化、私有权限、备份与轮换 | src/cli |

产品名称、收费版本、商品价格和设备组来自部署目录配置。身份适配器返回已经验证的稳定平台身份；核心不信任客户端自报的用户 ID、角色或付款结果。框架没有附带客户数据、真实支付账户或产品专属 Windows 代码。

## 2 账号与版本权益

内部 accountId 与外部身份的 provider、subject 分开保存。外部身份组合唯一，昵称不作身份依据。注册使用绑定该身份的一次性邀请，同时核实身份凭据；注册本身不授予付费权益。参考 HTTP 登录使用身份适配器，具体产品可以在受控后端另接密码与 MFA。

产品、收费版本和软件构建分别用 product、edition、releaseId 表示。一个账号可以同时拥有多个永久版本。升级新增目标版本权益，保留旧版本；不自动赠送中间版本。

### 历史授权认领

宿主先向可信平台核实购买凭证，再调用 `importEntitlement`。输入包含 source、reference、reason 和可选 betaAccess。reference 应稳定标识凭证来源，同一来源、凭证、版本不能被另一账号再次认领。

认领没有真实付款时不生成订单，授权的 order_id 可以为空。已有付费来源不会被覆盖；已撤销权益不会被认领恢复；重复核实保持幂等。平台角色移除不自动撤销已确认的永久授权。框架不公开用户自报身份组的认领接口。

### 普通版与 Beta

| 已核实资格 | 同版本普通版 | 同版本 Beta | 新收费版本 |
| --- | --- | --- | --- |
| 普通版 | 可用 | 不包含 | 不包含 |
| Beta | 可用 | 可用 | 不包含 |
| 升级购买 | 保留原版本 | 保留原资格 | 仅新增目标普通权益 |

`hasReleaseAccess` 检查账号状态、有效版本权益和同版渠道资格。实际下载服务必须调用渠道鉴权；许可证也签入 stable/beta 渠道和硬件摘要；签发与 SDK 验证都检查范围。撤销版本权益会清除 Beta，重新购买普通版不恢复旧 Beta。

`bestUpgradeOffer` 从账号有效旧版权益对应的固定升级商品中选择最低金额，同价按商品 ID 排序，不混合比较不同币种。历史实付额不参与计算。已拥有目标版、没有升级资格或币种混杂会被拒绝。

## 3 订单与设备规则

订单默认 24 小时有效，可配置 60 秒至 30 天。旧待付订单在首次升级时取得完整宽限期。独立附表保存截止时间；查询及核款即时检查，不依赖定时清理。

人工取消与过期分开处理。取消订单不能直接发放；过期单须提供 latePaymentReason。核款必须验证实际收款、金额、币种、唯一流水及购买资格。价格保存为订单快照，调价不改变旧单。

确认、发放、审计与通知在同一事务完成。异常到账先独立登记，再用于同账号新订单，或登记已完成的人工退款。订单与异常记录间统一防重用。系统不执行自动退款，也不把付款截图当作到账证据。

### 设备组与换绑

同组产品共享一台有效设备、冷却与额度，不同组独立。激活验证 Ed25519 私钥；同密钥但摘要变化按换绑处理。私钥与摘要同时复制仍须由原生端可信硬件措施解决。

| 事件 | 设备和额度结果 | 冷却结果 |
| --- | --- | --- |
| 首次激活 | 建立绑定，不扣额度 | 开始自然月冷却 |
| 免费资格成熟 | 不累计，不失效 | 使用前保留 |
| 成功换绑 | 免费优先，否则扣一次 | 重新开始 |
| 确认设备重置 | 按规则扣费；旧设备停续期 | 从重置时重新开始 |
| 重置后首次绑定 | 不再次扣除 | 保留重置时的冷却 |
| 购买或赠送次数 | 仅增加额度 | 不重置 |
| 密钥与摘要相同 | 不算换绑 | 保留原时间 |
| 激活失败 | 不消耗额度 | 不改变 |

月份使用配置的 UTC 偏移，保留时分秒，月末取目标月有效日。例如 UTC+8 的 1 月 31 日激活，4 月 30 日成熟，不是固定 90 天。重置需核对代次与费用；幂等重试不重复扣费，未绑定或等待重绑时不可再重置。

revokeAccess 撤销会话与未完成挑战，可同时停用设备续期。它不赠送换绑次数、不改变冷却，保留已经付费的重置。宿主还须同事务撤销网页会话、设备申请及确认票据。原离线许可证可用至到期。

## 4 接口与数据关系

参考服务默认监听 127.0.0.1:3100。普通 API 使用用户 Bearer 会话，管理 API 使用独立部署密钥；两种凭据不能互相替代。参考服务不接受浏览器 Origin，不使用 Cookie；网页应经自己的同源后端接入。完整参数与错误见 [API 契约](API.md)。

| 接口分组 | 典型入口 | 负责结果 |
| --- | --- | --- |
| 身份 | /v1/auth/register 与 login | 注册、会话与注销 |
| 用户业务 | /v1/me 与 /v1/orders | 自己的权益、设备与订单 |
| 激活 | /v1/devices/challenges 与 activate | 账号批准下的设备绑定 |
| 许可 | /v1/licenses/challenges 与 issue | 设备证明后签发短期许可 |
| 管理 | /v1/admin/accounts 与 orders | 启停、身份维护、额度、到账确认 |
| 分发 | /v1/admin/distributions | 预留编号、登记最终哈希与清单 |

历史认领、渠道检查、最低升级商品选择是宿主服务方法，不是上述参考 HTTP 服务新增的公开路由。产品层应先鉴权并核实证据，再调用这些方法。

### 数据与迁移

accounts 保存稳定账号；entitlements 保存永久权益；orders 保存订单；bindings 与 credits 保存设备组状态和额度。entitlement_imports 保存历史凭证归属，entitlement_channels 保存按版本的 Beta 资格。分发记录保留生成当时的身份快照，后续修改账号关联不改写历史。

迁移 6 增加 payment_exceptions，保存原订单、账号、实际流水、处理状态和退款或新订单关联。迁移 2 引入账号状态和迁移记录；迁移 3 将权益 order_id 改为可空并增加来源及渠道表，保留已有付款授权。升级前备份，降级应恢复与旧代码匹配的备份，不能只切换旧二进制。

嵌套事务使用 savepoint，宿主可以将产品会话撤销与核心状态变更放在同一事务。账号启停与可选 accountEnabled 策略作用于核心授权路径及幂等重放，不能只依赖网页隐藏按钮。

## 5 许可分发与安全边界

服务器与设备分别持有独立 Ed25519 密钥。许可证默认有效 15 分钟，包含账号、产品、收费版本、渠道、硬件摘要、设备、公钥指纹、绑定代次和有效期；客户端必须同时核实签名与预期范围。验签公钥需由可信发布渠道预置或更新，不能信任任意响应携带的新公钥。

数据库永久权益与短期许可证是不同对象。换绑或停用后旧设备不能刷新，但已经签发的离线许可证可能用到到期。本框架不能保证客户端不可修改、HWID 不可伪造或离线立即撤销。

### 用户专属文件的接入顺序

1. 宿主鉴权并选择收费版本、软件构建与渠道，预留分发编号。
2. 文件 worker 在可信基础产物中加入随机追踪标识，不写入长期登录凭据。
3. 完成产品格式校验和平台签名，计算最终 SHA-256。
4. 框架确认不可变的文件哈希与签名分发清单，文件进入私有存储。
5. 下载服务再次核实当前权益与渠道，再签发短时下载地址。

框架目前提供记录、签名清单和 Node 验证参考；示例仅生成带标记的 JavaScript 文件。它没有实现 EXE 水印、安装包工厂、Authenticode 签名、对象存储或真实下载网关。追踪标识是调查线索，不能单凭它认定用户泄露。

### 通知与运维

outbox 与业务同事务写入。参考 dispatcher 是单 worker、至少一次投递，重试可能重复通知；生产宿主负责调度、退避、事件去重和告警。通知失败不回滚已确认的权益。

私有文件保护、单进程锁、限并发 scrypt、可信代理限制、账号停用、加密备份恢复和签名密钥轮换已有实现。管理界面仍需产品提供 MFA 与具名操作员权限，根管理密钥不得进入浏览器、客户端或 Bot 消息。

## 6 运行维护与交付状态

使用 Node.js 24.19.0 或更新的 24.x、pnpm 11.25.0。先安装锁定依赖并运行 `pnpm check`；初次部署构建后运行 `pnpm init:local`，之后使用 `pnpm start`。初始化不覆盖已有配置，生产模式禁止本地开发身份验证器。配置方法见 [部署维护](OPERATIONS.md)。

维护前停止服务。使用受限口令文件执行 backup、restore 或 rotate-signing，口令不写命令行参数。备份采用认证加密，恢复只写新目录。原始文件总量上限为 256 MiB，仍兼容旧备份格式；这是有容量边界的内存实现，大规模制品不得塞进业务备份。核对 schema、目录配置、账号权益、设备冷却和密钥后再切换；不能直接复制正在写入的 SQLite 主文件并忽略 WAL。

### 当前验证

本次新增异常到账、渠道与摘要许可、安全恢复撤销和迁移 6。本地构建和 62 项测试通过；此前生产依赖审计未报告已知漏洞。GitHub Actions 曾明确因账号计费锁定而未启动；本地成功不代表远端 CI 通过，也不代表完成真实产品支付或硬件验收。

当前代码版本为 0.5.0。接入时固定审核合并后的提交或对应标签；SDK 新增必填的预期 fingerprint，旧许可证需重新签发。Git main 保存集成代码，短期分支通过 PR 合并。收费版本、软件构建版本、分发渠道与 Git 分支相互独立；运行数据库、私钥、环境配置和客户文件不得进入 Git。
