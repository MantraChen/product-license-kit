## 0.7 框架与宿主的当前边界

框架新增付费 Beta 同版补差、Beta 直购与带来源渠道条件的跨版升级。bestUpgradeOffer 的第三参数选择目标渠道，默认 stable；核款重新验证资格并保留已有 Stable 付款来源。商品仍使用现有迁移 6 的表。

## 1 架构与复用边界

产品网页、社区 Bot 和原生客户端通过产品后端进入框架。框架以 TypeScript 库提供事务化用例，也附带独立 HTTP 参考服务。Node.js 24 是运行基础。同步 Framework 使用内置 SQLite；AsyncFramework 使用 PostgresStore，业务方法必须 await，不能向同步构造器直接传 PostgreSQL 仓储。

| 层次 | 主要职责 | 代码位置 |
| --- | --- | --- |
| 核心策略 | 类型、自然月规则、签名 | src/core |
| 业务服务 | 同步与异步账号、订单、权益、设备、分发 | src/service.ts 及 src/async-service.ts |
| 适配器 | SQLite、PostgreSQL、协调、门户、Bot、身份与通知 | src/adapters |
| HTTP 边界 | 输入校验、会话、管理认证 | src/http |
| 客户端参考 | 挑战签名与许可证验签 | src/sdk |
| 运维工具 | 初始化、私有权限、备份与轮换 | src/cli |

产品名称、收费版本、商品价格和设备组来自部署目录配置。身份适配器返回已经验证的稳定平台身份；核心不信任客户端自报的用户 ID、角色或付款结果。框架没有附带客户数据、真实支付账户或产品专属 Windows 代码。

## 2 账号与版本权益

内部 accountId 与外部身份的 provider、subject 分开保存。外部身份组合唯一，昵称不作身份依据。注册使用绑定该身份的一次性邀请，同时核实身份凭据；注册本身不授予付费权益。参考 HTTP 登录使用身份适配器，具体产品可以在受控后端另接密码与 MFA。

产品、收费版本和软件构建分别用 product、edition、releaseId 表示。一个账号可以同时拥有多个永久版本。升级新增目标版本权益，保留旧版本；不自动赠送中间版本。

### 历史授权认领

宿主先向可信平台核实购买凭证，再调用 `importEntitlement`。输入包含 source、reference、reason 和可选 betaAccess。reference 应稳定标识凭证来源，同一来源、凭证、版本不能被另一账号再次认领。

认领没有真实付款时不生成订单，授权的 order_id 可以为空。已有付费来源不会被覆盖；已撤销权益不会被认领恢复；重复核实保持幂等。平台角色移除不自动撤销已确认的永久授权。框架不公开用户自报身份组的认领接口。

### 普通版与 Beta

| 已核实资格 | 同版本普通版 | 同版本 Beta | 新收费版本 |
| --- | --- | --- | --- |
| 普通版 | 可用 | 不包含 | 不包含 |
| Beta | 可用 | 可用 | 不包含 |
| 升级购买 | 保留原版本 | 保留原资格 | 仅新增目标普通权益 |

`hasReleaseAccess` 检查账号状态、有效版本权益和同版渠道资格。实际下载服务必须调用渠道鉴权；许可证也签入 stable/beta 渠道和硬件摘要；签发与 SDK 验证都检查范围。撤销版本权益会清除 Beta，重新购买普通版不恢复旧 Beta。

`bestUpgradeOffer` 从账号有效旧版权益对应的固定升级商品中选择最低金额，同价按商品 ID 排序，不混合比较不同币种。历史实付额不参与计算。已拥有目标版、没有升级资格或币种混杂会被拒绝。

## 3 订单与设备规则

订单默认 24 小时有效，可配置 60 秒至 30 天。旧待付订单在首次升级时取得完整宽限期。独立附表保存截止时间；查询及核款即时检查，不依赖定时清理。

人工取消与过期分开处理。取消订单不能直接发放；过期单须提供 latePaymentReason。核款必须验证实际收款、金额、币种、唯一流水及购买资格。价格保存为订单快照，调价不改变旧单。

确认、发放、审计与通知在同一事务完成。异常到账先独立登记，再用于同账号新订单，或登记已完成的人工退款。订单与异常记录间统一防重用。系统不执行自动退款，也不把付款截图当作到账证据。

### 设备组与换绑

同组产品共享一台有效设备、冷却与额度，不同组独立。激活验证 Ed25519 或 RSA-PSS 私钥持有；同密钥但摘要变化按换绑处理。私钥与摘要同时复制仍须由原生端可信硬件措施解决。

| 事件 | 设备和额度结果 | 冷却结果 |
| --- | --- | --- |
| 首次激活 | 建立绑定，不扣额度 | 开始自然月冷却 |
| 免费资格成熟 | 不累计，不失效 | 使用前保留 |
| 成功换绑 | 免费优先，否则扣一次 | 重新开始 |
| 确认设备重置 | 按规则扣费；旧设备停续期 | 从重置时重新开始 |
| 重置后首次绑定 | 不再次扣除 | 保留重置时的冷却 |
| 购买或赠送次数 | 仅增加额度 | 不重置 |
| 密钥与摘要相同 | 不算换绑 | 保留原时间 |
| 激活失败 | 不消耗额度 | 不改变 |

月份使用配置的 UTC 偏移，保留时分秒，月末取目标月有效日。例如 UTC+8 的 1 月 31 日激活，4 月 30 日成熟，不是固定 90 天。重置需核对代次与费用；幂等重试不重复扣费，未绑定或等待重绑时不可再重置。

revokeAccess 撤销会话与未完成挑战，可同时停用设备续期。它不赠送换绑次数、不改变冷却，保留已经付费的重置。宿主还须同事务撤销网页会话、设备申请及确认票据。原离线许可证可用至到期。

## 4 接口与数据关系

参考服务默认监听 127.0.0.1:3100。普通 API 使用用户 Bearer 会话，管理 API 使用独立部署密钥；两种凭据不能互相替代。参考服务不接受浏览器 Origin，不使用 Cookie；网页应经自己的同源后端接入。完整参数与错误见 [API 契约](API.md)。

| 接口分组 | 典型入口 | 负责结果 |
| --- | --- | --- |
| 身份 | /v1/auth/register 与 login | 注册、会话与注销 |
| 用户业务 | /v1/me 与 /v1/orders | 自己的权益、设备与订单 |
| 激活 | /v1/devices/challenges 与 activate | 账号批准下的设备绑定 |
| 许可 | /v1/licenses/challenges 与 issue | 设备证明后签发短期许可 |
| 管理 | /v1/admin/accounts 与 orders | 启停、身份维护、额度、到账确认 |
| 分发 | /v1/admin/distributions | 预留编号、登记最终哈希与清单 |

历史认领、渠道检查、最低升级商品选择是宿主服务方法，不是上述参考 HTTP 服务新增的公开路由。产品层应先鉴权并核实证据，再调用这些方法。

### 数据与迁移

accounts 保存稳定账号；entitlements 保存永久权益；orders 保存订单；bindings 与 credits 保存设备组状态和额度。entitlement_imports 保存历史凭证归属，entitlement_channels 保存按版本的 Beta 资格。分发记录保留生成当时的身份快照，后续修改账号关联不改写历史。

SQLite 迁移 7 增加 outbox_resources，迁移 8 增加 task_jobs 与 task_job_reviews。迁移 6 增加 payment_exceptions，保存原订单、账号、实际流水、处理状态和退款或新订单关联。迁移 2 引入账号状态和迁移记录；迁移 3 将权益 order_id 改为可空并增加来源及渠道表，保留已有付款授权。升级前备份，降级应恢复与旧代码匹配的备份，不能只切换旧二进制。

嵌套事务使用 savepoint，宿主可以将产品会话撤销与核心状态变更放在同一事务。账号启停与可选 accountEnabled 策略作用于核心授权路径及幂等重放，不能只依赖网页隐藏按钮。

## 5 许可分发与安全边界

服务器使用 Ed25519 签名根，设备独立使用 Ed25519 或 RSA-2048/PSS-SHA256 密钥。许可证默认有效 15 分钟，包含账号、产品、收费版本、渠道、硬件摘要、设备、公钥指纹、绑定代次和有效期；客户端必须同时核实签名与预期范围。验签公钥需由可信发布渠道预置或更新，不能信任任意响应携带的新公钥。

数据库永久权益与短期许可证是不同对象。换绑或停用后旧设备不能刷新，但已经签发的离线许可证可能用到到期。本框架不能保证客户端不可修改、HWID 不可伪造或离线立即撤销。

### 用户专属文件的接入顺序

1. 宿主鉴权并选择收费版本、软件构建与渠道，预留分发编号。
2. 文件 worker 在可信基础产物中加入随机追踪标识，不写入长期登录凭据。
3. 完成产品格式校验和平台签名，计算最终 SHA-256。
4. 框架确认不可变的文件哈希与签名分发清单，文件进入私有存储。
5. 下载服务再次核实当前权益与渠道，再签发短时下载地址。

框架目前提供记录、签名清单和 Node 验证参考；示例仅生成带标记的 JavaScript 文件。它没有实现 EXE 水印、安装包工厂、Authenticode 签名、对象存储或真实下载网关。追踪标识是调查线索，不能单凭它认定用户泄露。

### 通知与运维

outbox 与业务同事务写入。同步 dispatcher 是单 worker、至少一次投递，重试可能重复通知；异步 PostgreSQL 通知有持久任务、租约、心跳、退避和结果不明核销，宿主仍负责平台证据与实际启停。通知失败不回滚已确认的权益。

私有文件保护、单进程锁、限并发 scrypt、可信代理限制、账号停用、加密备份恢复和签名密钥轮换已有实现。可选通用门户提供 MFA 与具名操作员权限，产品也可使用自己的受控后台；根管理密钥不得进入浏览器、客户端或 Bot 消息。

## 6 运行维护与交付状态

使用 Node.js 24.19.0 或更新的 24.x、pnpm 11.25.0。先安装锁定依赖并运行 `pnpm check`；初次部署构建后运行 `pnpm init:local`，之后使用 `pnpm start`。初始化不覆盖已有配置，生产模式禁止本地开发身份验证器。配置方法见 [部署维护](OPERATIONS.md)。

维护前停止服务。使用受限口令文件执行 backup、restore 或 rotate-signing，口令不写命令行参数。备份采用认证加密，恢复只写新目录。原始文件总量上限为 256 MiB，仍兼容旧备份格式；这是有容量边界的内存实现，大规模制品不得塞进业务备份。核对 schema、目录配置、账号权益、设备冷却和密钥后再切换；不能直接复制正在写入的 SQLite 主文件并忽略 WAL。

## 接口失败与恢复责任

设备重置预览不扣次数；提交必须同时携带观察到的 generation 和 cost，并由服务器再次核对。绑定或费用改变时刷新并重新确认，不能静默改成另一种扣费。reset-pending 后首次激活不重复消费额度。指纹来自客户端，不等于硬件认证或 TPM。

付款超时先查询同一笔业务结果；取消、过期和真实到账是不同事实。流水去重与权益发放必须保持同一事务。外部验签、退款 API 与账单对账由宿主提供，框架只记录经验证的业务结果。

通知 outbox 由宿主主动调度；写入事件不等于通知到达。分发 finalize 后不可覆盖文件哈希。迁移前停止服务并备份，回退使用与旧代码匹配的数据，不能仅覆盖可执行文件。完整错误处理及检查命令见 CONTRACTS.md 和 OPERATIONS.md。

## 7 异步存储与任务协调

PostgresStore 使用真实异步连接池、SERIALIZABLE 事务、显式 unit 与保存点。业务、命令回执、审计及 outbox 原子提交；平台认证与消息发送在事务之外。可重试冲突由业务入口有限重试，提交结果不明先查业务结果，不假设写入失败。迁移独立使用 plk_pg_migrations、摘要和 schema advisory lock；不得与 SQLite 编号混用。

多节点共享限流需要一致 namespace、私有 HMAC secret 与策略，存储不可用时拒绝而非退回节点预算。持久任务通过 token、generation、TTL 和数据库租约拒绝过期 worker；sending 的外部结果不明进入 uncertain，只有核实未接收才可重试。同步 SQLite 的任务迁移 8 仅支持同一主机共享私有数据库，不能把文件放在网络共享上构造多节点。

订单、已完成且仍有权限的分发及管理审计支持游标分页，每页最多 100 条，游标绑定账号及列表类别；原无查询参数入口保留最近 100 条数组。详细接口与状态见 [存储](POSTGRESQL.md) 和 [协调](COORDINATION.md)。

## 8 可选门户与私信交互

PostgresPortal 与 createPortalApp 和 AsyncFramework 共用根仓储。OAuth state 绑定浏览器并在交换前原子消费；MFA 通过后更新 Cookie 与框架会话。普通会话默认 12 小时，可选保持登录 30 天；操作员最多 2 小时且空闲 30 分钟。敏感写入要求近期 MFA、当前权限和 CSRF，具名审计与业务同事务。必要 Cookie 的用途及期限有页面说明，不能据此宣称法律合规认证。

换绑先预览当前代次、免费日期与费用，再经明确勾选确认；意图绑定当前会话与资格快照，状态变化拒绝。该流程沿用核心自然月与额度规则，不包含产品的见证免费恢复。

PostgresKookBot 验证回调、原卡片、账号归属及一次性按钮。注册交接绑定指定 KOOK 身份、门户 namespace 与 epoch，网页仍核实 OAuth 及 MFA；不能作为原生邀请票据使用。通知有唯一归属，结果不明需核销。执行与发送开关缺省关闭。真实平台资格尚未开通，本地模拟不能算手机实传；完整配置见 [门户](PORTAL.md) 与 [Bot](BOT.md)。

## 9 原生 SDK 与恢复迁移

C# 和 Rust SDK 提供挑战签名、许可证及分发验签、Windows CurrentUser DPAPI 软件身份、受保护文件和范围绑定的 HWID 摘要。已完成本机 Windows x64 的双向身份互读及回环 HTTP；损坏密文拒绝替换，缺失身份默认拒绝新建。软件存储不等于 TPM，不替换产品现有原生协议；其他系统需单独验证，见 [SDK](../clients/README.md)。

PostgreSQL 共享签名策略要求候选节点用私钥证明就绪；指定轮换计划先取得加密备份回执，再由有租约的控制面启用。默认自动执行关闭，故障或结果不明暂停。备份覆盖签名钥、门户加密钥和业务数据；只恢复到空 schema，清除登录材料并暂停未完成外部任务。生产客户端必须先通过可信发布预置新公钥，服务端计划不能自行建立客户端信任。

通用 SQLite v6/v7/v8 离线兼容迁移先审核摘要、加密备份、锁源与封存，再对独占 PostgreSQL 目标整批导入；保留付费权益、额度、绑定和分发记录，清除登录材料，不重放历史通知。不导入产品 exa_ 表或 V5 数据，不自动切换生产。详见 [签名与恢复](POSTGRES-SIGNING.md) 和 [兼容迁移](SQLITE-POSTGRES.md)。
