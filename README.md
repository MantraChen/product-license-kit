# Product License Kit

一个可复用的产品授权与分发框架。把账号身份、版本权益、订单、设备绑定和分发追溯分开管理，通过适配器接入不同产品与社区平台。

**源码可见，仅允许许可证规定的非商业用途；欢迎提交 PR。** 使用 [PolyForm Noncommercial 1.0.0](LICENSE)，不属于 OSI 定义的开放源代码软件。第三方商用需另行获得授权；贡献前请阅读 [贡献说明](CONTRIBUTING.md) 和 [贡献授权协议](CONTRIBUTOR_AGREEMENT.md)。

## 当前状态

`0.1.0` 是可运行、可测试的 API 核心与接入参考实现。它适合非商业实验和扩展开发；生产接入还需要真实身份配置、管理端强认证、支付与交付适配器、备份及运维措施。没有附带现成的支付账户、Bot、客户数据或 Windows 产品代码。

| 能力 | 当前实现 |
| --- | --- |
| 身份 | 可插拔验证器；KOOK access token 服务端验证；本地开发凭据 |
| 注册 | 绑定外部身份的一次性邀请，票据哈希存储，身份必须匹配 |
| 权益 | 多产品、多收费版本、永久权益、固定价格升级且保留旧权益 |
| 订单 | 服务端价格快照、人工到账确认、付款流水去重、幂等发货 |
| 设备 | 每账号每设备组一台；跨产品可共用组；Ed25519 持钥证明 |
| 换绑 | 按自然月冷却；成熟后免费资格不失效、不累积；付费/管理员次数 |
| 许可证 | 服务端签名的短期设备许可证；独立客户端验签与作用域检查 |
| 分发 | 用户分发编号、身份历史快照、最终文件哈希、签名清单、追溯查询 |
| 通知 | 事务 outbox、失败可重试、可选 KOOK 私信适配器 |
| 管理 | 独立管理员 API、身份变更、赠送次数、撤销权益、审计记录 |

浏览器门户、OAuth 跳转回调、KOOK 按钮/Webhook、商户自动到账、Windows TPM/HWID 收集、EXE 水印与 Authenticode 签名、对象存储下载尚未内置。分发演示使用带标记的 JavaScript 文件，不能把它当作已实现的 EXE 防破解器。

## 运行

需要 Node.js **24.19.0 或更新的 24.x**、pnpm **11.25.0**。SQLite 使用 Node 内置模块，无需安装本地编译工具链。

```sh
git clone https://github.com/MantraChen/product-license-kit.git
cd product-license-kit
pnpm install --frozen-lockfile
pnpm check
pnpm demo
```

`demo` 启动一个临时本地 HTTP 服务，用内存数据库和随机凭据执行注册、模拟人工付款、升级、绑定设备、签发和验证许可证、生成用户文件。不会真实付款或向 KOOK 发消息。示例文件写入 Git 忽略的 `.data/demo-artifacts/`。

启动持久化 API：

```sh
pnpm build
pnpm run init:local
pnpm start
```

默认地址 `http://127.0.0.1:3100`。健康检查：`GET /health`。初始化会在 `.env` 与 `.data/` 生成随机开发凭据和签名密钥；不会覆盖已有配置。`TOKEN_IDENTITY_PATH` 只能用于本地开发，生产模式拒绝启用。

参考 [API](docs/API.md)、[架构和业务规则](docs/ARCHITECTURE.md)、[接入指南](docs/INTEGRATION.md)、[部署说明](docs/OPERATIONS.md)。

## 适配另一个产品

1. 在 `examples/catalog.json` 的副本中定义产品、收费版本、固定升级价和设备组，设置 `CATALOG_PATH`。金额使用最小货币单位的整数；示例价格仅为测试数据。
2. 决定哪些产品共用设备组。相同组意味着共享一台设备、冷却时间和额外次数；不同组互不影响。
3. 实现 `IdentityProvider.verify`，验证平台凭据后返回稳定用户 ID。不能把用户自己提交的 ID 当作验证结果。
4. 在客户端安全保存设备私钥，接入设备挑战、授权申请与许可证验签。Node 参考 SDK 位于 `src/sdk/`，其他语言按 [协议说明](docs/PROTOCOL.md) 实现。
5. 为实际文件类型实现个性化、平台签名和下载服务。调用分发预留与确认 API，登记最终文件哈希。

框架核心没有硬编码任何产品名称、KOOK ID、银行账户、支付密钥或硬件序列号。KOOK 是可选适配器，收费策略与设备组策略由部署方配置。

## 目录与版本

```text
src/core/          策略、类型、签名
src/service.ts     事务化业务用例
src/adapters/      SQLite、KOOK、本地开发身份
src/http/          API 边界、认证和输入校验
src/sdk/           Node 客户端参考实现
src/cli/           本地初始化
examples/         虚构产品配置与完整演示
tests/            业务、安全边界、API 与适配器测试
docs/             接入、部署、协议、贡献和版本计划
.github/          CI、PR 模板、维护规则
```

`main` 保存集成代码，短期功能分支通过 PR 合并，`v0.x.y` 标记框架发布。客户产品收费版本、二进制构建版本与框架版本各自独立。实际客户配置、数据库、日志、密钥和用户文件放在仓库外的私有存储。详见 [仓库治理](docs/REPOSITORY.md)。

## 安全边界

本地客户端可以被修改，本框架不能保证不可破解。HWID 只作为非可信变更信号；持有私钥也不等于硬件证明。旧设备撤销后不能刷新许可证，但已签发的离线许可证仍可能使用到到期。默认许可证有效期为 15 分钟，账号版本权益本身没有到期时间。

管理 API 当前使用高熵部署密钥，适合受控服务间调用。不要把管理密钥放进浏览器、客户端或 Bot 消息。生产管理界面应通过独立后台接入 SSO/MFA 和操作员审计。详细边界见 [安全策略](SECURITY.md)。
